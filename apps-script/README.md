# 修正「LINE 登入驗證失敗」

先前使用的 `2012115242` 與本網站登入頻道不符。LINE 官方 `@liff/util` SDK 的 `extractChannelIdFromLiffId` 會取 LIFF ID 的數字前段；`@liff/init` 以它核對 access token 的 `client_id`。本網站 LIFF ID 是 `2012115245-A7HBSYsv`，因此登入 Channel ID 應為 **`2012115245`**。

**線上立即修復：**原 Apps Script → 專案設定 → 指令碼屬性，將 `LINE_LOGIN_CHANNEL_ID` 改為 `2012115245`，儲存後重新登入網站，再試代登記。不必更改 LIFF ID 或 Web App 網址，單純修改指令碼屬性也不需要重新部署網站。

本次 `complete/Code.gs` 的預設值已改正，亦會把先前錯填的 `2012115242` 視為本網站的舊錯誤設定，改用固定的 `2012115245` 驗證，不會修改原屬性或接受錯誤頻道的權杖。若使用這份程式，請更新原 Apps Script Web App 的新版本。其他明確指定的頻道仍會受到嚴格比對；不符時會顯示 LINE 回傳與後端設定的公開數字 ID，方便排查，過期權杖會明確要求重新登入。

檢查依據：LINE 官方 SDK npm 發布套件 `@liff/util@2.31.2`、`@liff/init@2.31.2`。測試會交叉核對前端 LIFF ID 與後端預設頻道，並驗證缺少屬性、舊錯誤屬性、正確教練、錯誤頻道、過期權杖及非教練。

後端新增唯讀 `getStudentProfile`，只接受通過 LINE 權杖、頻道、有效期限及教練名單驗證的查詢。查詢必須同時指定 `lineId` 與 `studentId`（舊單人帳號的 `studentId` 為空字串）。不回傳身分證、不修改學生資料或試算表結構；一般 `checkUser`、`getStudentStats` 與 `getCoachData` 回應仍不含這些新增私密欄位。不要把註冊資料直接加回公開統計 API。

**部署順序：**先將本次 `complete/Code.gs` 更新至原 Apps Script Web App 的新版本，再發布前端。包含上一版 LINE Channel 設定修正，仍優先使用原指令碼屬性。舊後端尚未更新時，基本資料區會顯示更新提示，原訓練統計仍可檢視。讀取失敗可按「重新讀取基本資料」。

本機驗證涵蓋：教練查看代表與其他學生資料、空欄位與舊帳號、錯誤學生／帳號、非教練、缺少／過期權杖、錯誤頻道、無資料寫入與公開 API 不洩漏。測試使用模擬 LINE 與試算表；上線前仍須在原 Apps Script 驗證實際 LINE 存取。

# 專屬教練課按帳號收費

- 團課維持按學生人數扣額與計費。既有訂單金額與名額不會被改寫，也不會自動退款。
