# 月繳團課統一方案

所有會員等級同價，個人單堂團課優惠價也不套用於月繳：

| 每堂時長 | 堂數 | 每人原價 | 每人優惠價 |
| --- | --- | --- | --- |
| 一小時 | 4 堂 | 1,200 | 1,000 |
| 一小時 | 5 堂 | 1,500 | 1,250 |
| 二小時 | 4 堂 | 2,400 | 2,000 |
| 二小時 | 5 堂 | 3,000 | 2,500 |

後端 `MONTHLY_GROUP_TARIFFS` 統一管理方案。新增課程的價格預覽由後端依當月該星期實際四／五堂計算，不採信呼叫者的堂數、基準價或會員等級。新增與編輯已公告月繳方案時，五個舊會員價格欄位均寫入相同方案價；預約報價、學員預約、教練月繳代登記皆重新從課程時長與堂數決定方案，不使用舊 VIP 欄位收費。已存在的訂單、歷史付款、名額與請假補課規則不追溯變更。

新課程的完整日期數需符合標示堂數，不能重複日期或把五堂標為四堂。舊課程若僅保留首堂日期，仍可使用原名稱中的堂數；其他未公告的舊方案保留第一級方案價作為所有會員的統一價格，不自行套用四／五堂方案。學員仍逐人顯示原價與優惠價、依實際參加人數合計並分別建單，送出前核對後端報價。

前端新增及編輯月繳課程不再出現五組會員收費欄位，改顯示上述四組方案；其他舊方案只提供一個統一收費欄位。日文翻譯、既有前端文字編碼及品牌圖片編碼均保留。

**部署順序：**將本次完整 `complete/Code.gs` 更新至原 Apps Script Web App 部署的新版本，再發布前端；沿用 API URL、OAuth 權限與排程，不需新增工作表或重裝觸發條件。`getSlots`／`getPricingPreview` 提供 `monthlyUniformPricingVersion: 1`，新版前端在舊後端會停止月繳價格相關操作，避免套用舊會員折扣。

測試：`node apps-script/tests/monthly-uniform-prices.test.cjs`、`node tests/group-pricing.test.cjs`，涵蓋四組方案、五種會員等級、四／五堂預覽、偽造價格、新增／編輯欄位一致、個別學員建單、教練代登記、舊報價拒絕與舊訂單保留；使用模擬 LINE 及試算表，不操作線上資料。

# 個別學員單堂團課價格

入口：「教練後台 → 學員名單與資料 → 指定學員的『團課價格』」。可分別設定一小時及二小時單堂團課價格；同帳號的學員各自儲存，不共用。**未設定或清空時使用原價：一小時 300 元、二小時 550 元**，不再套用該課程的會員等級價，也不在個人價格上再打會員折扣。0 表示免費，金額須為有效非負數，最多小數點後兩位。

此設定只套用一／二小時單堂團課，月繳依最上方統一方案收費，專屬教練課仍依原方案及共享名額收費；其他單堂時長仍使用課程等級價。原本已成立的訂單與歷史付款金額不會變更。單堂二小時原價為 550 元，月繳的原價與優惠價依其獨立方案公告。

後端首次儲存會自動建立「學員團課價格」工作表，欄位為 LINE_ID、學生編號、一小時團課價格、二小時團課價格、更新時間、設定教練。以帳號＋學生編號定位，舊單人帳號的空字串學生編號亦支援。只由已驗證教練呼叫 `setStudentGroupPrices` 寫入，與預約共用 `ScriptLock`，失敗回復原價格；讀取不建立工作表。欄位不符或重複紀錄會拒絕操作，不能用任一重複列默默決定收費。

學員卡片及確認預約畫面逐人顯示暱稱、原價、優惠價（若有優惠）及帳號合計；無暱稱以「學員 1」等代稱，不用真實姓名當暱稱。後端自行取得每人的價格並分別寫入該學員訂單；教練單堂代登記同樣適用。送出前重新報價，核對合計及每一位學員的已確認價格，即使總額相同但個人分攤改變，也拒絕寫入並要求重新確認。

**部署順序：**將本次完整 `complete/Code.gs` 更新至原 Apps Script Web App 部署的新版本，再發布前端；沿用原 API URL、OAuth 權限及既有排程。`getSlots`／`getCoachData` 新增 `studentGroupPricingVersion: 1`，新版前端在舊後端會停止個人團課預約、停用價格設定，避免顯示錯誤舊價。不需要手動建立工作表、搬移既有學生資料或重裝排程。

驗證：`node apps-script/tests/student-group-prices.test.cjs` 涵蓋教練權限、個別學員、預設 300／550、不同價格分單、竄改、逐人報價過期、單堂代登記、月繳／私人課保留、清空、免費、格式錯誤、回復與舊帳號；均使用模擬 LINE 與試算表，不操作線上資料。

# 後端統一授權、計價與寫入（securityVersion 2）

**使用 `complete/Code.gs` 整份更新原 Apps Script Web App 部署，再發布對應前端。**本版所有網站 API 都需有效 LINE access token；前端由 LIFF 取得目前登入者的 token，透過 HTTPS POST 傳送。後端每次先呼叫 LINE 驗證 token 的頻道、有效期限及持有人，再決定權限，不採信傳入的 `isAdmin`、教練 ID 或宣稱的帳號身分。驗證完成後才讀寫工作表；寫入共用原 `ScriptLock`，LINE 網路驗證不佔用寫入鎖。

- 學員只能讀取、註冊、預約自己帳號，付款後五碼只能修改自己帳號的審核中訂單，必須為五位數字。不能查詢其他人的帳號、日誌或付款。後端核對目前會員及學生資料，不使用呼叫者提供的會員等級、學生姓名、名額數或應付價格。
- 教練管理資料、開課、刪課、核准預約、寫日誌、取消、刪單、確認現金收款、請假補課、代登記、歷史補登及授課教練管理，都由後端確認 token 持有人在 `ADMIN_LINE_IDS`。原「開啟學生畫面」仍可運作，只有真正通過驗證的教練能操作指定學生帳號；新增授課教練姓名不會授予登入權限。
- 一般預約不再有未註冊者自行傳入 `paidPrice` 的路徑。後端讀取單堂團課個人價格／預設原價，月繳依公告統一方案、其他單堂時長讀取課程會員等級價格，私人課從課程設定計算方案費用與共享名額，核對允許場地、學生人數與重複預約，最後在鎖內重新計價並寫入。`expectedTotalPrice` 與 `expectedStudentPrices` 只用來核對已顯示的報價，不能指定收費；價格變更會拒絕寫入，要求重新確認。
- 試算表原有課程收費不會批次改寫。單堂一／二小時團課依個人價格政策；月繳依統一方案，其他單堂時長以課程試算表價格為準。價格建議在 `pricingPreview_`，月繳不再套用 `getVIPDiscount_`。私人課保留本來後端實際使用的折扣，前端只顯示後端報價。教練經驗證後可設定個人團課價格及其他非固定方案課程價格，此授權調價與學員預約指定金額是不同操作。
- 日誌日期、5 分鐘單位、各項最多 2 小時、學生與訂單關聯均由後端檢查。訂單先經核准才能結課，同一已完課訂單不能重複建立日誌；失敗會回復日誌與訂單狀態。收款註記、價格與學員姓名會檢查格式，不將使用者輸入的試算表公式寫入姓名或匯款後五碼欄。

新增 API：`getBookingQuote`（學員本人或已驗證教練的目標帳號）、`getPricingPreview`（教練的價格建議及私人課初始設定）、`getPaymentSummary`（教練的每月收入與個別學員累積付款）。`getCoachData` 也回傳伺服器計算的 `paymentSummary`，包含金額與異常資料計數。前端的折扣、團課價格規則、私人課乘算、代登記合計與付款加總函式已移除，僅格式化及顯示後端結果。學員的 `getSlots` 不再傳回全部等級價目或私人課原始設定字串，改提供這個帳號的 `priceQuote`。

所有回應附 `securityVersion: 2`。新版前端遇到缺少此版本的後端會停在登入錯誤，不進入管理或預約畫面。更新後端後，舊前端因缺少 token 會被拒絕，請緊接著發布新版前端；本次 HTML 的 `script.js`／日文檔已增加版本參數以重新載入快取。原 API URL、試算表、OAuth 權限與自動清理排程皆沿用，不需新增觸發條件。

**金鑰與公開設定：**本次檢查未發現前端硬編碼的私密金鑰。API 網址與 LIFF ID 是瀏覽器登入及呼叫服務所需的公開設定，付款收款資訊也需顯示給付款學員；它們不是授權依據。真正的 Channel secret、服務金鑰等如有使用，應保存在 Apps Script「專案設定 → 指令碼屬性」，由 `PropertiesService` 讀取，不能放進前端、API 回應或 GitHub 程式碼。`LINE_LOGIN_CHANNEL_ID` 既有屬性仍沿用。登入 token 不寫入試算表或應用程式日誌，網路錯誤亦不回傳含 token 的原始 URL。後端程式不隨網頁送給瀏覽器，但若 GitHub 倉庫公開，倉庫中的 `Code.gs` 本身仍可被閱讀，因此後端程式碼也不能硬編碼私密金鑰。

驗證：`node apps-script/tests/security-boundaries.test.cjs` 涵蓋所有 API 的未登入／過期／錯誤頻道、管理員冒用、跨帳號、金額／會員等級／姓名／名額竄改、私人課方案與場地、過期報價、重複與回復、付款歸屬及日誌結課。`node tests/authenticated-api.test.cjs` 檢查前端統一 token、舊後端拒絕與錯誤不洩漏憑證；價格及付款原有測試已改為直接執行後端實作。測試使用模擬 LINE 回應與試算表，不操作線上資料。

# 個別學員歷史預約補登

入口為「教練後台 → 學員名單與資料 → 指定學員的『補登歷史預約』」。可填寫歷史課程名稱、上課日期與起訖時間、地點、授課教練（可用現有名單建議或自行填寫舊教練）、課程金額、已收款／尚未收款、預約成功／已完課／已取消，以及原預約日期。原預約日期未填寫時採上課日期；只能補登台灣時間已結束的課程，原預約日期不可晚於上課日期。

已收款且狀態為預約成功或已完課的補登會計入**指定學員**的累積付款；同帳號兄弟姊妹分開，尚未收款及已取消不計。月收入採「原預約日期」的月份，不把今天補登的舊付款全算進今天所在月份。補登後名單付款與收入統計會重新讀取；補登本身不增加完成堂數、能力時數或次數，這些仍以原有訓練日誌為準。歷史預約補登與「補登日誌」為不同功能。

後端 `coachAddHistoricalBooking` 及唯讀 `getHistoricalBookingOptions` 均要求有效 LINE 教練權杖、正確頻道、有效期限與管理員名單。寫入共用 `ScriptLock`，只接受該帳號內唯一的學員編號，姓名由後端學員資料取得，支援舊單人帳號的空字串學員編號。相同送出識別碼重試不重複建立；不同識別碼仍會檢查同學員、課程、日期與時間的重複紀錄，以及仍可查得的原始預約。若原課程早已刪除、資訊無法比對，教練仍需核對舊紀錄。

首次儲存自動建立「歷史預約紀錄」工作表 A～P：紀錄編號、補登時間、LINE_ID、學生編號、學生姓名、課程名稱、上課日期、開始時間、結束時間、上課地點、授課教練姓名、課程金額、付款狀態、原預約日期、課程狀態、送出識別碼。若同名表已有其他用途、標題不符，會拒絕寫入；不變動既有「預約名單」、課程名額、會員與日誌。獨立保存讓已下架、未在系統開課的歷史課程也能補登，且不重新上架供學生預約。

`getStudentStats` 新增完整 `bookingHistory`（含一般訂單的已完課紀錄及此學員的手動補登）；原 `bookings` 仍僅供追蹤中訂單，維持排除已完課與不加入手動歷史的行為。後台「檢視資料 → 歷史預約紀錄」改用完整歷史。`getCoachData` 的原 `bookings` 保留，另以 `historicalBookings` 回傳手動補登供付款統計使用，不讓舊的對帳、取消、結課按鈕誤操作獨立歷史紀錄。補登表單可新增與檢視；本次未提供修改或刪除既有手動歷史的介面。

**部署順序：**先將本次 `complete/Code.gs` 完整更新至原 Apps Script Web App 部署的新版本，維持原 API 網址，再發布前端。保留原本的 `appsscript.json` 權限與排程，不需額外安裝新觸發條件。連到舊後端時，補登視窗會顯示尚未啟用並停用送出；原預約功能保留。

測試：`node apps-script/tests/historical-bookings.test.cjs`（權限、學生歸屬、日期金額、重複、重試、舊資料與名額／日誌不變）及 `node tests/coach-payments.test.cjs`（歷史付款歸屬、未收款／取消排除與原月份）。所有測試使用模擬資料，不寫入線上試算表。

# 無人預約課程自動刪除（開課前 6 小時）

以 **Asia/Taipei 台灣時間**的開課時間為準，到了開課前 6 小時（含該時刻）仍沒有有效預約，就從「可用時段」刪除課程。例如 19:00 開課，13:00 起符合清理條件。單堂團課、專屬教練課均適用；月繳套裝以完整年份中**第一堂**的開課時間計算，不會在套裝中途刪除某一堂。

「審核中」、預約成功、已完課及舊版空白或未知狀態均視為有預約，只有明確「已取消」不算。名額已被佔用、名額資料異常、重複課程編號、無法辨識的日期／時間、缺少年份的舊月繳資料及有請假／補課關聯的課程都會保留。只刪除課程列，不修改預約單、付款、會員、日誌或請假資料。首次啟用也會清理已過截止時間的舊空課。

**啟用步驟（需要更新後端；單純發布網站不會啟用）：**

1. 用原 Apps Script 專案的部署者帳號，將 `complete/Code.gs` 整份取代原程式。

  "https://www.googleapis.com/auth/script.external_request",
